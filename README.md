# فریا · FARYA Chef Console

سامانهٔ محاسبهٔ **بهای تمام‌شده** و **قیمت‌گذاری منو** برای سرآشپزِ رستوران فریا.
رابطِ فارسی (RTL)، تقویمِ شمسی، و محاسبهٔ زنده از مادهٔ خام تا حاشیهٔ سود.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # خروجی در dist/
npm run preview    # پیش‌نمایشِ نسخهٔ ساخته‌شده
npm run typecheck  # بررسی تایپ‌ها
npm run fonts      # بازسازی public/fonts/fonts.css پس از افزودن فونت
```

---

## ۱. فونت مدام (Modam)

فونتِ اصلیِ کل برنامه **مدام** است (طراحیِ سید ناصر خادم — ۸ وزن: ExtraLight، Light،
Regular، Medium، SemiBold، Bold، ExtraBold، Black، به‌همراه نسخهٔ وریبل).

> مدام یک فونتِ تجاری است و همراهِ این مخزن منتشر نمی‌شود. فایل‌ها را باید خودتان
> (با لایسنسِ معتبر از [fontiran.com/fonts/modam](https://fontiran.com/fonts/modam))
> تهیه و در پوشهٔ `public/fonts` قرار دهید.

### قرار دادن فونت‌ها

```
public/fonts/
  Modam-ExtraLight.woff2
  Modam-Light.woff2
  Modam-Regular.woff2
  Modam-Medium.woff2
  Modam-SemiBold.woff2
  Modam-Bold.woff2
  Modam-ExtraBold.woff2
  Modam-Black.woff2
```

یا فقط نسخهٔ وریبل (سبک‌تر و بهتر برای وب):

```
public/fonts/Modam[wght].woff2     ← یا  Modam-Variable.woff2
```

سپس یک‌بار اجرا کنید:

```bash
npm run fonts
```

اسکریپت نامِ فایل‌ها را می‌خواند، **خانواده، وزن و subset** را تشخیص می‌دهد و
`public/fonts/fonts.css` را بازنویسی می‌کند. نام‌های فارسی (مثل `مدام-Regular.woff2`)
نیز پشتیبانی می‌شوند. اگر هیچ فایلی از مدام نباشد، برنامه به‌طور خودکار با
**وزیرمتن** (موجود در مخزن) کار می‌کند — پس تا قبل از افزودن مدام هم همه‌چیز درست نمایش داده می‌شود.

### فونت‌های همراه (در مخزن هستند)

| خانواده | نقش |
|---|---|
| **MODAM** | متنِ فارسیِ کل برنامه (با جایگزینِ وزیرمتن) |
| **Outfit** | لاتینِ رابط — هندسی و هماهنگ با هندسهٔ مدام |
| **Bodoni Moda** | لاتینِ نمایشی — سریفِ هنری برای وردمارک و تیترهای لاتین |

هر سه به‌صورت **local** (بدون وابستگی به اینترنت یا CDN) بارگذاری می‌شوند.

## ۲. داده‌های مبنا

داده‌های اولیه مستقیماً از فایل `menu cost-1400-04-16.pdf` استخراج و در
`src/data/seed.ts` نشانده شده‌اند:

| موجودی | تعداد |
|---|---|
| مواد اولیه (با تاریخچهٔ قیمت) | ۱۱۳ |
| آیتم‌های منو | ۲۶ |
| دستورهای نیمه‌ساخته (سس‌ها، خمیرها …) | ۱۷ |
| آیتم‌های سربار | ۹ |
| ردیف‌های دستور پخت | ۳۲۸ |

## ۳. فرمول محاسبه (مطابق فایل منبع)

```
بهای مواد       = Σ (مقدار × قیمتِ جاریِ ماده)
جمع × ضریب      = بهای مواد × ضریبِ دستور (پیش‌فرض ۳)
سربارِ پایه     = (جمع × ضریب) / تعداد پرسِ ماهانه × Σ سربارِ انتخابیِ آیتم
ضریبِ اضافی     = سربارِ پایه × ضریبِ اضافیِ سربار
بهای ناخالص     = (جمع × ضریب) + سربارِ پایه + ضریبِ اضافی + هزینهٔ ظرف
بهای تمام‌شده   = بهای ناخالص (برای هر آیتم)  ·  بهای هر واحد (برای نیمه‌ساخته‌ها)
سود             = قیمت منو − بهای تمام‌شده
حاشیهٔ سود      = سود ÷ قیمت منو
فودکاست         = بهای مواد ÷ قیمت منو
قیمت پیشنهادی   = بهای تمام‌شده ÷ (۱ − حاشیهٔ هدف)
```

دستورهای نیمه‌ساخته به‌صورت بازگشتی (با تشخیصِ دور) قیمت‌گذاری می‌شوند؛
اگر سرباری را روی آیتمی انتخاب نکنید، هزینهٔ آن صفر منظور می‌شود.

## ۴. بخش‌ها

- **نگاه کلان** — KPIهای زنده، نمودار ترکیب هزینه، آیتم‌های زیرِ حاشیهٔ هدف، شاخص سلامتِ اقتصادی منو
- **مواد اولیه** — جست‌وجو، مرتب‌سازی، افزودن/ویرایش/حذف، ثبت قیمت با **تقویم شمسی**
  (تاریخِ خالی ⇒ امروز به‌طور خودکار)، نمودار روند قیمت، تشخیص تغییرِ قیمت
- **آیتم‌ها و دستور پخت** — تعریف آیتم + موادِ تشکیل‌دهنده با مقدار، ضریبِ هر آیتم،
  انتخاب سربارها از لیست، هزینهٔ ظرف، گروه‌بندی (منو / نیمه‌ساخته)
- **هزینه‌های سربار** — ۹ آیتم مبنا + افزودن آیتم جدید، خلاصهٔ اثرِ هر سربار روی منو
- **قیمت‌گذاری منو** — جدولِ زنده (فیلتر، جست‌وجو، مرتب‌سازی، فقط زیرِ هدف)، افزایشِ
  گروهی (+۵٪)، گردکردنِ هوشمند، خروجی اکسل، اِعمال قیمت پیشنهادی، و تبِ **کارت‌های منو**
- **تنظیمات** — نام رستوران/سرآشپز، حاشیهٔ هدف، تعداد پرسِ ماهانه، **ضریبِ اضافیِ سربار**،
  واحد پول، پشتیبان/بازیابی JSON، خروجی CSV، و کارتِ **سلامت داده‌ها** برای رفع تضادهای
  قیمتِ به‌جامانده از فایل منبع

## ۵. طراحی و ریسپانسیو

- تم: سبزِ تازه، کتان و گرافیت — هماهنگ با نگاهِ ورزشکار/سلامت‌محورِ سرآشپز
- **لوگو**: حرف F که خودش یک شاخهٔ سبز است (ساقه + دو برگ)، با هالهٔ نوری،
  تابشِ عبوری و تکانِ ملایمِ برگ‌ها — فایل‌های مستقل در `public/brand/`
- **واکنش‌گرایی**: از ۳۲۰px تا ۱۹۲۰px
  - `< 900px`: ناوبریِ پایین + منوی کشویی، جدول‌ها تبدیل به **کارت‌های ردیف**،
    مودال‌ها به‌صورت شیت از پایین، فهرستِ آیتم‌ها به‌صورت لیست → جزئیات
  - `900–1199px`: نوارِ کناریِ باریک (فقط آیکون)
  - `≥ 1200px`: نمای کامل با نوارِ کناری
- **افکت‌ها**: نورِ دنبال‌کنندهٔ نشانگر روی کارت‌ها، هاله‌های رنگیِ متحرک،
  درخشش روی دکمه، موجِ کلیک، نمایشِ تدریجی هنگام پیمایش، شمارندهٔ اعداد،
  و **هر آیکون یک انیمیشنِ مخصوصِ خودش** (ضربانِ قلب، تکانِ برگ، چرخشِ بروزرسانی،
  باز شدنِ درِ سطل زباله، پریدنِ سکه، جرقه، کشیده شدنِ تیک …)
- همهٔ انیمیشن‌ها به `prefers-reduced-motion` احترام می‌گذارند و فونت‌ها محلی‌اند

## ۶. انتشار روی گیت‌هاب

```bash
cd farya-app
git init
git add .
git commit -m "FARYA Chef Console — اولین نسخه"

# مخزن را در github.com بسازید (بدون README/LICENSE) و سپس:
git remote add origin https://github.com/USERNAME/farya-chef-console.git
git branch -M main
git push -u origin main
```

> فایل‌های فونت را نیز `git add public/fonts` کنید (در `.gitignore` مستثنی نشده‌اند).
> برای فایل‌های حجیم می‌توانید از Git LFS استفاده کنید.

هر push/pull request روی `main`، workflowِ `.github/workflows/ci.yml` را اجرا می‌کند
(نصب، `typecheck`، `build` و بارگذاریِ خروجی).

## ۷. دپلوی روی ورسل

**روش ۱ — از طریق گیت‌هاب (توصیه‌شده):**
1. به [vercel.com](https://vercel.com) وارد شوید و *Add New → Project* را بزنید.
2. مخزنِ `farya-chef-console` را Import کنید.
3. تنظیمات به‌طور خودکار شناخته می‌شود (Framework: Vite):
   - Build Command: `npm run build`
   - Output Directory: `dist`
   - Install Command: `npm ci`
4. *Deploy* را بزنید. هر push روی `main` به‌طور خودکار دپلوی می‌شود.

**روش ۲ — با CLI:**
```bash
npm i -g vercel
vercel          # دپلویِ پیش‌نمایش
vercel --prod   # دپلویِ نهایی
```

فایل `vercel.json` در مخزن تنظیماتِ لازم را دارد: بازنویسیِ SPA، کشِ یک‌ساله برای
فونت‌ها و خروجیِ build، و هدرهای امنیتی.

داده‌ها در `localStorage`ِ مرورگر ذخیره می‌شوند (نیازی به دیتابیس نیست)؛
از بخشِ تنظیمات می‌توانید فایل پشتیبان (JSON) بگیرید و بازیابی کنید.

## ۸. پایگاه‌دادهٔ سوپابیس (ذخیره‌سازی دائمی)

برنامه به‌صورت پیش‌فرض روی مرورگر کار می‌کند. برای اینکه **همهٔ داده‌ها واقعاً و
برای همیشه** در پایگاه‌داده بمانند، پنج اسکریپتِ آماده در پوشهٔ `supabase/`
قرار دارد.

### گام ۱ — ساخت پروژه

1. به [supabase.com](https://supabase.com) بروید و یک پروژهٔ جدید بسازید.
2. از **Project Settings → API** دو مقدار را بردارید:
   - `Project URL`
   - `anon public` key

### گام ۲ — اجرای اسکریپت‌ها

در **SQL Editor** پروژه، فایل‌ها را **به همین ترتیب** اجرا کنید:

| فایل | کاری که انجام می‌دهد |
|---|---|
| `supabase/01_schema.sql` | جدول‌ها، اندیس‌ها، تریگرها و توابعِ تقویمِ شمسی |
| `supabase/02_functions.sql` | موتورِ محاسبهٔ بهای تمام‌شده و رویه‌های عملیاتی |
| `supabase/03_rls.sql` | امنیتِ سطحِ ردیف (RLS)، دسترسی‌ها و Realtime |
| `supabase/04_seed.sql` | داده‌های واقعیِ منو (۴۳ آیتم / ۱۱۳ ماده / ۳۲۸ ردیف دستور) |
| `supabase/05_verify.sql` | بررسیِ صحت — اجرا کنید و مطمئن شوید همه PASS است |

> ترتیب مهم است: ۰۱ باید پیش از ۰۲ اجرا شود (ستونِ `gdate` به تابعِ تبدیل وابسته است).

### گام ۳ — اتصالِ برنامه

فایل `.env.example` را کپی کرده و نامش را `.env.local` بگذارید، سپس پر کنید:

```bash
cp .env.example .env.local
# سپس مقادیر را ویرایش کنید:
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

و سرور را دوباره راه‌اندازی کنید:

```bash
npm run dev
```

از این لحظه، نشانگرِ بالای کارتِ سرآشپز وضعیت را نشان می‌دهد
(**ذخیره در پایگاه‌داده** = متصل) و با کلیک روی آن همگام‌سازیِ دستی انجام می‌شود.

### روی ورسل

همین دو متغیر را در **Vercel → Project → Settings → Environment Variables**
اضافه کنید و دوباره دیپلوی کنید.

### نکته‌های فنیِ مهم

- **موتورِ محاسبه در پایگاه‌داده هم پیاده شده است** (`cost_all()`, `cost_item()`)
  و خروجی‌اش با موتورِ تایپ‌اسکریپتِ برنامه (`src/lib/calc.ts`) روی تمامِ
  ۴۳ آیتم و ۵۱۷ مقدار **کاملاً یکسان** است (تستِ تطبیقی انجام شده).
- **تقویمِ شمسی در SQL** با الگوریتمِ JDN نوشته شده و با موتورِ برنامه روی
  **۱۳٬۱۴۹ تاریخ** در هر دو جهت تطبیق داده شده (۰ اختلاف).
- توابع با `plpgsql` نوشته شده‌اند تا PostgreSQL آن‌ها را درونِ پرس‌وجوها
  «inlined» نکند؛ در غیر این صورت زمانِ برنامه‌ریزی به‌شدت بالا می‌رود
  (۱۴ دقیقه در برابرِ ۰٫۳ ثانیه).
- **همگام‌سازی اتمیک است**: رویهٔ `save_state()` کلِ وضعیت را در یک تراکنش
  به جدول‌های رابطه‌ای تجزیه می‌کند — یا همه چیز ثبت می‌شود یا هیچ چیز.
- **هیچ داده‌ای از دست نمی‌رود**: هر ذخیره یک نسخه در `app_state_history`
  می‌گذارد و هر تغییر در `audit_log` ثبت می‌شود.
- **اتصالِ اینترنت قطع شود** هم برنامه کار می‌کند؛ تغییرات در مرورگر می‌مانند و
  با وصل شدنِ دوباره خودکار همگام می‌شوند.
- اگر دو دستگاه همزمان ویرایش کنند، وضعیت‌ها **ادغام (merge)** می‌شوند،
  نه اینکه یکی دیگری را از بین ببرد.
